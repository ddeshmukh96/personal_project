########## HAVING Clause

  SELECT city,COUNT(name) FROM student GROUP BY city HAVING marks>82;
  
  ERROR 1054 (42S22): Unknown column 'marks' in 'having clause'

  SELECT city,COUNT(name) FROM student GROUP BY city HAVING MAX(marks)>82;


When you use GROUP BY city, MySQL aggregates all rows per city — so there
is no single marks value anymore for the group.

HAVING works after grouping, so it can only use:
Aggregated columns (like AVG(marks), MAX(marks), SUM(marks)),
or Columns in the GROUP BY clause (like city here).
That’s why marks (a non-grouped, non-aggregated column)
doesn’t exist at that point — MySQL throws an error.

@@@@@@@@@@@@@@@@@   AUTO_INCREMENT – Quick Notes

Default start: 1 → increments by 1 for each new row.

Change start: use AUTO_INCREMENT = X in CREATE TABLE or ALTER TABLE.

Deleted IDs: not reused; next ID = highest existing + 1.

Manual insert: allowed; future IDs continue from the highest value.

Ensures unique primary keys automatically.

SYNtax :

************ Default Behavior **********

CREATE TABLE courses (
    course_id INT PRIMARY KEY AUTO_INCREMENT,
    course_name VARCHAR(50)
);

INSERT INTO courses (course_name) VALUES ('Maths');
INSERT INTO courses (course_name) VALUES ('English');

When a column is defined as AUTO_INCREMENT, MySQL automatically generates unique numbers for new rows.

By default, the first value starts at 1.

Each subsequent row increases by 1.

************ Changing the Starting Value ***************

a) During Table Creation
CREATE TABLE courses (
    course_id INT PRIMARY KEY AUTO_INCREMENT,
    course_name VARCHAR(50)
) AUTO_INCREMENT = 100;


The first inserted row will have course_id = 100.

Next row → 101, and so on.

b) After Table Creation
ALTER TABLE courses AUTO_INCREMENT = 200;


The next inserted row will have course_id = 200.

AUTO_INCREMENT always continues from the highest value + 1.
