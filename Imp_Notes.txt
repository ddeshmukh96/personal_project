Case 1 : Binary Search Using a Dictionary (Finding the word “paper”)

A dictionary is sorted alphabetically, so we can use binary search to quickly find a word.

Step 1: Start in the Middle

Suppose the dictionary has about 100,000 pages.

Open the dictionary roughly in the middle.

You see the word “mango”.

Since “paper” comes after “mango”, we can eliminate the first half of the dictionary.

👉 Pages left to search: last 50,000 pages

Step 2: Check the End of the Remaining Section

Now look at the last page of this remaining section.

You see the word “zebra”.

Since “paper” comes before “zebra”, the word must lie between “mango” and “zebra”.

Now split this range in half.

👉 Pages eliminated: about 25,000
👉 Pages left: 25,000

Step 3: Go to the Middle Again

Open the dictionary in the middle of this new range.

You land on the word “vineyard”.

Since “paper” comes before “vineyard”, we can eliminate the section from “vineyard” to “zebra”.

👉 Pages left: about 12,500

Step 4: Narrow It Further

Again, open the middle of the remaining section.

You see the word “peacock”.

Since “paper” comes before “peacock”, the word must be between “orange” and “peacock”.

👉 Pages left: very few (around 10–15 pages)

Step 5: Linear Search at the End

Now that only a small number of pages remain, it’s easy to scan page by page and find “paper”.

1️⃣ Algorithm-Style Steps (Binary Search – Dictionary Example)

Algorithm: Find a word using Binary Search

1. Start with a dictionary sorted in alphabetical order.
2. Set low to the first page and high to the last page.
3. While low ≤ high:

1. Open the dictionary at the middle page.
2. Compare the middle word with the target word (“paper”).
3. If the middle word is equal to the target word:

* Word found. Stop.

4. If the middle word comes alphabetically before the target word:
* Eliminate the first half.
* Set low = mid + 1.

5. If the middle word comes alphabetically after the target word:
* Eliminate the second half.
* Set high = mid − 1.

4. If the loop ends and the word is not found:
* The word is not present in the dictionary.

Case 2 : Dictionary is jumbled / randomised (Linear Search Algorithm)

Binary search only works on sorted data.
If the dictionary is not sorted alphabetically, then:
We cannot eliminate half of the remaining pages.
We have no idea whether the word is on the left or right.
So binary search is not possible.

👉 In this case, we must use Linear Search.

# Why is Binary Search ( O(\log n) )?

## What is Binary Search?

* Binary search is an efficient algorithm to find a target value in a **sorted array**.
* It works by repeatedly " dividing the search space in half ":

  * Compare the target with the **middle element**.
  * If equal, return the index.
  * If the target is smaller, continue the search in the " left half ".
  * If the target is larger, continue in the " right half ".
* This process repeats until the target is found or the search space is empty.

---

## Analyzing the Time Complexity

Let:

* ( n ) = number of elements in the array.
* Each step **halves** the size of the search space.

---

### Step 1: Initial Search Space Size

* Start with ( n ) elements.

---

### Step 2: After 1 Comparison

* Search space is halved:

  [
  \frac{n}{2}
  ]

---

### Step 3: After 2 Comparisons

* Search space is halved again:

  [
  \frac{n}{2^2} = \frac{n}{4}
  ]

---

### Step ( k ): After ( k ) Comparisons

* Search space size:

  [
  \frac{n}{2^k}
  ]

---

### When does the search end?

* The search ends when the search space is reduced to 1 element:

  [
  \frac{n}{2^k} = 1
  ]

* Multiply both sides by ( 2^k ):

  [
  n = 2^k
  ]

* Taking logarithm base 2 on both sides:

  [
  \log_2 n = k
  ]

---

## Conclusion

* The "maximum number of comparisons" ( k ) required to find the
  target (or conclude it’s not present) is:

  [
  k = \log_2 n
  ]

* Hence, "binary search runs in ( O(\log n) ) time".

---

## Intuition

@@ In binary search, the search space is halved at each step. After k steps, the remaining elements
   are n / 2^k. The algorithm stops when n / 2^k = 1, giving k = log₂ n. Hence, the time complexity is O(log n).
